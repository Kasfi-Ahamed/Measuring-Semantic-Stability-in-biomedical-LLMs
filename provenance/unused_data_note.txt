Amended 2026-10-05. The first version of this note described one directory. It was wrong,

================================================================================
WHY THIS NOTE WAS AMENDED
================================================================================
The original inventory asked du for an explicit list of directories under ~/data, so it
reported only the directories it was told to look at. ~/data/semeval2015_task14 was never
on that list and so never appeared, and the note was written as though ~/data/share were
the only holding. It was not. There were two, 12.8 MB in total, holding the same releases
in two forms. Deleting only the first would have left 831 clinical narratives on disk and
a provenance note stating the matter was closed.

The lesson, which is the reason this paragraph exists: an inventory built from a list of
names can only ever confirm the names it was given. The directory listing came first the
second time.

================================================================================
WHY BOTH WERE DELETED RATHER THAN ARCHIVED
================================================================================
  Neither raised an integrity question, only a data-holding one. Credentialed PhysioNet
  material whose approval for the intended use was still pending should not be copied to
  institutional storage, where it would persist for years unused and unaudited. Both
  holdings were de-identified clinical narratives, 1,562 note files between them.

  The decisions were Kasfi Ahamed's: holding 1 on 2026-10-05, holding 2 on 2026-10-05
  immediately after it was found, each authorisation scoped to that one directory. Nothing
  else was deleted. The standing instruction against deleting anything remained in force
  everywhere else.

  Recovering either, if anyone ever needs to, means a fresh credentialed download from
  physionet.org. The SHA256SUMS.txt shipped with the release lets a new copy be checked
  against what was held, and the two tree digests above let each tree be checked whole.
  Holding 2 is reconstructible from holding 1 by unpacking the three 2015 Task 14 archives;
  the de-duplication that produced test_unique/ is not documented anywhere and would have
  to be redone from scratch.
